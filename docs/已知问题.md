# 已知问题和后面可以做的事

- 没有任何手机结果。小米 15 Pro 的 HyperOS 版本、实际独占低延迟、USB DAC 的设备类型都还不知道。V2.1 的测量流程、左右麦映射、USB DAC 和路由切换都还没在这台手机上跑过。
- 频谱降噪的 5.33 ms 只是 48 kHz 宿主上的算法延迟。打开之后的端到端延迟没有测，不能说仍在 10–20 ms 里。所以它默认关闭。
- 双麦合成在宿主上能算出梳状抵消（8 样本延迟时 3 kHz 附近抵消）。手机上的麦距没有测，不能假设合成后是平的。
- 开放或半开放耳机的直达声梳状听感没有验收。
- 没有获得授权的普通话语音材料，因此没有做数字噪声或 MHINT 一类的可懂度测试，也不能把纯音拟合当成语音验证。
- 手机麦克风没有厂家校准文件。未校准档不套修正曲线。主观匹配和参考麦两档只有用户真的做了才能选，应用不会假装已完成。
- 没有做对侧掩蔽。两耳差大约 40 dB 时只会警告并停止加大自动补偿。
- 声学端到端延迟没有测过。宿主上的分频群延迟不能拿来当耳机延迟。
- 重采样是线性插值，只适合很小的时钟差。大偏差会丢样或补零。
- 压缩是左右联动的峰值包络，不是独立左右，也不是 RMS。
- 多段 IIR 有频率相关的群延迟。段数增加时 1 kHz 群延迟从大约 28 样本升到大约 52 样本（48 kHz 宿主测试）。
- 响度匹配是用增益和补偿量做的粗估算，上限 ±6 dB，会写进输出增益。它不是响度模型。
- A/B 是一套参数平滑切到另一套，不是两套处理同时交叉淡化。
- 安全限幅是采样峰值。没有真实峰值，没有 SPL。
- 图示均衡 16 kHz 在采样率太低、超过 0.45 倍采样率时设计会失败，并保留上一组稳定系数。48 kHz 下 16 kHz 可以通过。
- 只打了 arm64 Debug APK。没有 release 包，也没有 32 位 ABI。
- lint 有 19 条 warning，没有 error。
- 蓝牙、通话和厂商音频策略都可能让实际路径和请求不一样。界面应把这种差别标出来，但不能在没插上手机时证明它。

后面若在真机上确认了突发帧数和稳定路由，再考虑：更小的输出缓冲、质量更好但仍有界的重采样、以及把分频群延迟写进诊断页的“DSP 算法延迟”一栏。在那之前不要改安全逻辑去换更低的纸面延迟。
