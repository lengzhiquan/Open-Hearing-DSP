# 小米 15 Pro 验证指南

这次没有接上小米 15 Pro，也没有查到这台机器当前的 Android / HyperOS 精确版本。下面每一项都是**未跑**。不要把文档里的宿主测试数字当成这台手机的延迟。

优先路线：手机内置麦 → USB-C 数字 DAC → 有线耳机。蓝牙和其他路由可以试，延迟不保证。这是个人实验，不是助听器。

安装 Debug APK（只含 arm64-v8a）后：

1. 第一次点「开始」应先要麦克风权限，Android 13+ 还要通知权限。拒绝麦克风时不应采集。允许之后通知里应能看到正在采集，并且可以点停止。
2. 刚打开流时必须没有声音。有线耳机或 USB 耳机类型核对后才会平滑出声。USB DAC 如果被系统报成 USB 设备而不是 USB 耳机，必须再确认一次。没确认就应保持静音。
3. 增益从 0 附近听。界面出现正增益警告时再决定要不要加。dBFS 不是耳机声压级。
4. 诊断页核对：真实设备 ID 和名字、采样率、声道、AAudio 还是 OpenSL、独占还是共享、低延迟还是 None、framesPerBurst、回调帧数、缓冲容量和大小、环占用、DSP 微秒和回调预算、XRun 或“不可用”、时间戳或“不可用”。估计延迟和手填的声学延迟必须是两行不同的字。
5. 若输入是单声道，左右应一样，界面应写明没有双耳空间信息。
6. 播放中拔出耳机或 DAC：应立刻没声并停止，不会自己再开。插回后必须手动再点开始。
7. 输出在扬声器或听筒时，不确认就没有声音。确认过一次之后如果路由再变，应停止，并且不会自动回到扬声器。
8. 切到蓝牙：应先停在确认框，文案里写明延迟不保证。
9. 来电或被别的应用抢走音频焦点：应静音或停止。通话结束不应自动从扬声器出声。
10. 在系统设置里撤销麦克风权限：回到应用应停止。
11. 切到后台再回来，前台服务还在时采集可以继续；从最近任务划掉应停止。
12. 均衡、单段、多段来回切，听是否有爆音。多段旁路重组应接近原声，但 IIR 分频有群延迟，不会和输入逐样本相同。
13. 把实验限幅旁路掉，安全限幅仍应限制大信号。不要用很大的正增益对着扬声器做这项。
14. 声学延迟：在已确认的耳机路由上点测试脉冲，用另一台录音设备同时录脉冲和耳机声，再量时间差，把毫秒数手填进设备页。应用不会自己算出这个数。
15. 长听 15 分钟以上，看环占用是否一直涨、XRun 是否持续增加、有没有突然的故障静音。

任何一步和上面不一致，以手机上的现象为准，并记下来。不要用这份指南里的宿主群延迟冒充小米的结果。
