# 输入模式、设备身份和输出

个人实验。默认输入不跟随系统，固定手机内置麦克风。输出跟随系统默认路由，但保留 V1 的保护：路由变化时原生侧静音并停止；输出变成扬声器时不经确认不出声，确认过一次之后路由再变也不会自动回到扬声器。

## 三种输入

| 模式 | 标识 | 行为 |
| --- | --- | --- |
| 立体声双麦（默认） | `stereo-dual-mic` | 请求能以 2 声道打开的 `TYPE_BUILTIN_MIC`。打不开 2 声道就停止，不会把单声道复制后叫做立体声双麦。 |
| 双麦合成单声道 | `dual-mic-mono-sum` | 仍打开那只双声道麦，两路平均后送给两耳。切换大约 20 ms 平滑。 |
| 仅顶部 | `top-mic-mono` | 只选择声道数最大为 1 的内置麦。没有这只麦就提示，不用别的麦冒充。顶部在左还是右必须在这台手机上核对；没核对时，如果误开成立体声，处理会静音。 |

左右互换大约 20 ms 交叉。校正曲线打在互换之前的物理声道上。

小米 15 Pro（2410DPN6CC）上一次 V1 列表里：设备 id 23 是可立体声的内置麦，用户听感是顶部在右、底部在左；设备 id 25 是顶部单声道内置麦。同一次列表还有非麦克风类型 18（通话）、16（FM）、类型值 25（远程子混音，不是设备 id 25）、28（回声参考）。这些类型不进常规输入列表，只出现在设备页的诊断文字里。那次观察不能当成所有机型的结构，左右映射也不能照搬。

## 不按 id 记忆

持久身份是类型 `BUILTIN_MIC`、声道数、`address`、`productName`。当次打开的 `deviceId` 可以写进记录，重启或热插拔后不拿它做匹配。宿主逻辑测试用了一份按这次观察编的设备表（address 是占位符，不是从手机读出来的字符串）：把 id 23 改成 99 或 77 之后，仍按身份选中原来的立体声麦，不会去抓碰巧占用旧 id 的通话设备。

`setDeviceId` 只是请求。打开后比对实际 id 和声道数。不一致就关闭、静音，并写明这次不能当作该模式的校准。Oboe 若回退到别的设备，同样按不一致处理，不自动换麦，也不自动改模式。

外接带麦的 USB 或蓝牙设备接入时，输入选择仍指向内置麦。输出可以跟着系统走。设备列表变化时，现有保护会先停下来，需要手动再开始。

高级设置里可以手动指定别的麦克风或钉住输出。启用时界面写明校准失效、需要重测。

## 双麦相加不是平的

两只有间距的麦直接平均，会在部分频率抵消。宿主用闭合式计算：48 kHz、右路延迟 8 个样本（大约 0.17 ms）时，125 Hz 附近两路相加约 +6.0 dB，3000 Hz 处抵消到数值下限（约 -160 dB）。所以双麦合成不能假设频响仍然平坦。真机上的梳状深度取决于麦距和朝向，还没测。

开放或半开放耳机还会让直达声和处理后的声音叠在一起，听感上的梳状滤波也还没在耳机上验收。
