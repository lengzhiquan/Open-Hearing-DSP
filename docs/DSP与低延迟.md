# DSP、路由和延迟

这是个人音频实验，不是助听器，也不是医疗器械。dBFS 是满刻度相对电平，不能换成耳机里的声压级。正增益可能损伤听力，也可能和麦克风形成啸叫。

## 全双工

输出回调是时钟。回调里对输入流做超时为 0 的 `read()`，写入固定 8192 帧的单生产者环，再按输出块取出。不是两条互相等待的阻塞循环。

环满时丢掉新数据并计数。占用超过高水位时，消费端把读指针跳回目标附近，计数为过载。数据不够时输出 0 并计一次欠载。缓冲不会变大。

采样率不一致或时钟慢慢漂移时，用线性插值，比例限制在基准比率的大约 ±0.3%。偏差更大时靠丢样/补零把占用拉回来，而不是把缓冲越积越长。线性插值会带来轻微染色，界面上能看到当前比率。

输入声道按打开流之后的实际数量处理。单声道会复制到左右，界面写明这不是双耳空间信息。立体声均衡左右分开。压缩检测用左右较大值，避免声像被两侧不同增益拉开。

## 回调里不做的事

实时回调里没有分配、锁、文件、日志或等待。参数用三槽发布：音频线程最多试两次，失败就用上一份。增益、静音和模式用一阶平滑。滤波器在增益或类型变化时先淡到干声再换系数，避免系数突然跳变。

非有限输入或系数会故障静音，直到手动清除。

## 处理顺序

1. 输入增益（-24..+24 dB）
2. 10 段图示均衡，中心 31、62、125、250、500、1000、2000、4000、8000、16000 Hz，每段 ±12 dB，Q 固定约 1.414，左右独立
3. 8 段参数均衡：峰值、低架、高架、高通、低通，频率、增益、Q、开关，左右独立
4. 动态：关 / 单段 / 多段，大约 40 ms 交叉淡化；没选中的检测器仍在跑
5. 可旁路的实验限幅
6. 输出增益（-24..+12 dB）和左右增益
7. 不可关的安全限幅：门限 -1 dBFS，即时启动，约 100 ms 释放，然后再硬钳到门限。这是采样峰值，没有前瞻，不是真实峰值，也没有 SPL 校准
8. 静音包络。不安全路由是硬零，不是慢慢淡出

V1 路径默认没有 AI、VAD、噪声门、语音增强或 AEC。V2.1 在这条链路前面增加了可选的麦克风修正（未校准时是直通）、输入模式平滑、以及默认关闭的频谱降噪和啸叫检测。噪声底限控制默认关，打开后只限制弱段增益，不声称提高信噪比。拟合出来的多段压缩用分析滤波器的频段 RMS 做检测；高级设置里原来的实验压缩仍是峰值包络。细节和来源标签见 `docs/算法与拟合.md`。安全限幅仍不能关。测量模式另有 -18 dBFS 上限，并且不把麦克风信号送到耳机，只送测试音。

启动时增益目标可以是 0 dB，但静音包络从 0 开始，而且在路由核对之前回调直接写零。

## 分频

多段是 4 到 8 段。分频是两个串联的巴特沃斯二阶，也就是 Linkwitz-Riley 4。低频段还会经过更高分频点的低通+高通之和，用来补上同样的相位。旁路某一段时，这段仍然留在分频里，只是压缩增益为 1，否则重组会缺一块。

下面是 48 kHz 宿主测试里打印出来的数，不是手机测量。

补偿后的脉冲响应与“各级全通级联”的参考最大绝对误差约 8e-7。补偿后的正弦幅度在 80、250、1000、5000、10000 Hz 上偏离 0 dB 不超过约 0.05 dB。

不做相位补偿、直接相加时，同样的正弦可以偏到大约 -4.4 dB（8 段、10 kHz）。所以不能把未对齐的频段加在一起。

1 kHz 处的群延迟（样本，48 kHz）：

| 段数 | 样本 | 大约时间 |
| --- | --- | --- |
| 4 | 27.96 | 0.58 ms |
| 5 | 44.25 | 0.92 ms |
| 6 | 48.45 | 1.01 ms |
| 7 | 50.45 | 1.05 ms |
| 8 | 51.78 | 1.08 ms |

这是 IIR 的频率相关群延迟，不是固定缓冲，也不是声学端到端。段数越多，1 kHz 附近的群延迟越大。动态处理会再改变音色：宿主测试里，4 段中只让第 3 段以 8:1 压缩，1 kHz 正弦相对“全旁路重组”低了 2.097 dB。

## 路由

优先 AAudio、独占、低延迟、48 kHz、Float。失败就按共享、I16、设备原生采样率、OpenSL ES 往下试，每次都写进尝试日志。音源不会偷偷从 UNPROCESSED 改成 MIC。只有系统属性明确写支持时才请求 UNPROCESSED。`getInputPreset` 只表示我们请求了什么，不证明 HAL 没有处理。

AGC/NS/AEC 只有在分配了 session 时才能尝试关闭。默认不分配，以免拉高延迟。打开“分配 session”后，界面显示 available / create / enabled。即便 enabled 为 false，厂商 HAL 仍可能处理，这一项标成未知。

有线耳机和 USB 耳机类型核对后可以出声。USB 设备/配件、蓝牙、扬声器、未知类型都必须确认。扬声器文案写明啸叫风险。路由回调和每个输出块里的设备 ID 比对都会在原生侧硬静音并停止，不依赖界面上的旧状态。拔出或设备列表变化同样停止。扬声器不会自动恢复。焦点长期丢失会停止；短暂打断只静音，焦点回来时只有仍是已确认的非扬声器路由才恢复。

## 延迟要分开看

界面上分开显示：

- DSP 处理时长和它占本次回调预算的比例。这不是整机 CPU。
- 环占用和输出缓冲，单位毫秒。
- Oboe `calculateLatencyMillis`，标成估计，失败就是不可用。
- 时间戳使用 `CLOCK_MONOTONIC`，读不到就写不可用。
- 声学端到端：应用不会自动测。设备页可以手填，记录里和估计值分开保存。

10 ms 是愿望，小于 20 ms 是初期目标，不是保证。蓝牙不保证延迟。

测试脉冲是用户按下后才发的 1 ms 升余弦，峰值 -20 dBFS，并且还要经过安全限幅。路由没核对时会拒绝。它只是给外部录音一个标记，不是自动声学测量。
